# Admin runbook

For whoever deploys and looks after Invoice Intake. Day-to-day settings (threshold, tolerances, vendors) are changed by the AP manager in the app's **Settings** page; this runbook covers everything else.

## Production layout (Render + Cloudflare R2)

| Piece | Where | Defined in |
|---|---|---|
| PostgreSQL `invoice-db` | Render (free plan) | `render.yaml` |
| API `invoice-intake-api` | Render web service, Docker | `render.yaml` |
| UI `invoice-intake-ui` | Render web service, same Docker image | `render.yaml` |
| Uploaded files + page images | **Now:** the API service's local disk (`/app/storage`). **Later:** a Cloudflare R2 bucket | env vars `STORAGE_*` / `S3_*` |
| AI model | Google Gemini API | env var `GEMINI_API_KEY` |

**Free-tier limits (checked 2026-10-27):** services sleep after 15 minutes without traffic and take about a minute to wake; 750 instance hours per month are shared by both services; **the free database expires 30 days after it is created** (14 days' grace, then deleted) and has no backups; Gemini's free tier allows 15 requests per minute. Fine for a demo — move to paid plans before real use.

> **Files are not permanent yet.** The deploy uses local storage. On Render's free plan a service's disk is wiped on every restart, redeploy and 15-minute sleep. Database records survive, but the uploaded PDFs and page images do not: the review screen then shows *"Page image not available"*, and Retry answers *"The original file is no longer stored. Please upload it again."* This is acceptable for a demo only. To keep files, [switch to Cloudflare R2](#switch-to-cloudflare-r2-permanent-file-storage). It is free up to 10 GB, needs no code change, and takes about 10 minutes.

## First deployment (local storage)

You need a GitHub account, a Render account (render.com, sign in with GitHub) and a Gemini key.

1. **GitHub.** Create an empty *private* repository on github.com (no README, no .gitignore), then from the project folder:
   ```bash
   git remote add origin https://github.com/<you>/invoice-intake.git
   git push -u origin main
   ```
   `.env` is git-ignored, so your keys are not uploaded. Check on github.com that no `.env` file appears.
2. **Render: create the services.** Dashboard → *New* → *Blueprint* → connect GitHub and pick the repo → Render reads `render.yaml` and shows 3 resources (`invoice-db`, `invoice-intake-api`, `invoice-intake-ui`). It asks for every value marked `sync: false`:

   | Variable | Value |
   |---|---|
   | `GEMINI_API_KEY` | a key from aistudio.google.com/apikey (create a **new** one for production) |
   | `SEED_CLERK_PASSWORD`, `SEED_MANAGER_PASSWORD` | strong passwords, at least 10 characters. **Never the README demo passwords.** The API refuses to start without them (`APP_ENV=production`) |
   | `API_BASE_URL` (UI service) | type `https://placeholder` for now; it is fixed in step 4 |

   `SESSION_SECRET` is generated by Render automatically. `STORAGE_BACKEND=local` is already set in `render.yaml`. Click *Apply*. The first build takes about 5–10 minutes.
3. **Check the API.** Open the API service and copy its public URL (e.g. `https://invoice-intake-api.onrender.com`). Open `<url>/health`; it should show `{"status":"ok","database":"ok"}`. If it doesn't, read the *Logs* tab (see Troubleshooting).
4. **Connect the UI.** UI service → *Environment* → set `API_BASE_URL` to that API URL (with `https://`, no trailing `/`) → *Save*. The UI redeploys. Free services can't call each other privately, so it must be the public URL.
5. **Smoke test.** Open the UI service's URL, log in as `clerk@meridian.test` with your `SEED_CLERK_PASSWORD`, upload a fresh invoice from `data/dev/`, wait for it to finish, open it (or see it auto-approved), and approve it. Log in as `manager@meridian.test` and check that the Dashboard counts it.

## Switch to Cloudflare R2 (permanent file storage)

The R2 code is already in the app (`app/storage.py`, `S3Storage`); only settings change. Files uploaded **before** the switch are not copied over, so re-upload any you still need.

1. **Create the bucket.** cloudflare.com → sign up / log in → *R2 Object Storage* (a payment card may be required even for the free tier) → *Create bucket* → name `invoice-intake-files` → keep it **private** (no public access).
2. **Create a token.** R2 → *Manage R2 API tokens* (*API → Manage API tokens*) → *Create API token* → permission **Object Read & Write** → *Specify bucket* → `invoice-intake-files` → *Create*. Copy these three values immediately. The secret is shown only once:
   - **Access Key ID**
   - **Secret Access Key**
   - **S3 endpoint**: `https://<account-id>.r2.cloudflarestorage.com`. Use the account endpoint, without the bucket name on the end.
3. **Change the Render settings.** API service → *Environment* → edit:

   | Variable | New value |
   |---|---|
   | `STORAGE_BACKEND` | `s3` |
   | `S3_ENDPOINT_URL` | the S3 endpoint from step 2 |
   | `S3_BUCKET` | `invoice-intake-files` |
   | `S3_ACCESS_KEY` | the Access Key ID |
   | `S3_SECRET_KEY` | the Secret Access Key |
   | `S3_REGION` | `auto` |

   Delete `STORAGE_LOCAL_PATH` (it is ignored for `s3`, so leaving it is harmless). *Save* → the API redeploys.
4. **Make it permanent in the repo.** In `render.yaml`, delete the two local-storage entries and uncomment the R2 block under them, then commit and push. Otherwise a future Blueprint sync could switch back to local.
5. **Check.** Upload an invoice and open it in the review screen (the page image must show). In Cloudflare → R2 → the bucket, a folder named after the document id should appear with `original/` and `pages/` inside. Restart the API (*Manual Deploy → Restart*) and confirm the image still shows.

**Same switch for local Docker** (optional): put the same `STORAGE_BACKEND=s3` and `S3_*` values in `.env`, then `docker compose up -d`. Leave it on `local` for everyday development. Files then stay in `./storage/` on your machine.

Every API start runs `alembic upgrade head` and the seed (both are safe to repeat), so new code deploys need no manual steps.

## Routine tasks

| Task | How |
|---|---|
| **Deploy new code** | Push to `main`; Render redeploys both services automatically. Watch the API's *Logs* tab for `Application startup complete` |
| **Change the approval threshold / tolerances / vendors** | Manager → **Settings** page. Every change is in `audit_log` (`settings_changed`, `vendor_created`) |
| **Retry failed invoices** | Clerk → **Upload** page → **Retry** on the red row. Common causes: Gemini quota (`429`, wait a minute), unreadable file (ask the vendor for a new copy). After a restart, anything that was mid-way is marked *"Processing was interrupted by a server restart. Click Retry."* |
| **Reset a password** | Change `SEED_CLERK_PASSWORD` / `SEED_MANAGER_PASSWORD` in the API's *Environment* tab → save (redeploys). The seed resets the hash at start-up |
| **Rotate the Gemini key** | Create a new key in Google AI Studio → update `GEMINI_API_KEY` on the API service → after the redeploy, delete the old key in AI Studio |
| **Rotate R2 keys** (after switching to R2) | Create a new R2 token → update `S3_ACCESS_KEY` / `S3_SECRET_KEY` → delete the old token |
| **Rotate `SESSION_SECRET`** | Edit it on the API service. Everyone is logged out (tokens last 8 hours anyway) |
| **Switch to Claude** | Set `LLM_PROVIDER=anthropic`, `LLM_MODEL=claude-opus-5-5` (or `claude-haiku-5-5` for lower cost) and `ANTHROPIC_API_KEY`. Re-run the evaluation before relying on it |
| **Watch logs** | Render → service → *Logs*. Each pipeline step logs `document_id` and `duration_ms`; LLM calls log tokens |

## Back up and restore the database

The free Render database has **no backups and expires after 30 days**. From any machine with the PostgreSQL client tools:

```bash
# copy the "External Database URL" from Render → invoice-db → Connect
pg_dump --no-owner --format=custom "<external-database-url>" > invoice-$(date +%F).dump

# restore into a new database (e.g. after upgrading the plan or moving to Neon/Supabase)
pg_restore --no-owner --dbname "<new-database-url>" invoice-YYYY-MM-DD.dump
```
Then point the API's `DATABASE_URL` at the new database. Uploaded files live in R2 and are not affected.
**Before day 30:** upgrade `invoice-db` to a paid plan in Render, or dump → restore into another Postgres host.

## Run the evaluation

Locally, with Docker running and a Gemini key in `.env`:
```bash
docker compose exec api python -m eval.run_eval --note "what changed"           # test set
docker compose exec api python -m eval.run_eval --dataset dev --prompt extract_v2 # tune here only
python -m eval.plot_sweep eval/results/<test>.json eval/results/dev/<dev>.json  # chart
```
Results land in `eval/results/`. Never change prompts, rules or thresholds because of *test* results — investigate on `data/dev` instead.

## Troubleshooting

| Symptom | Likely cause | Fix |
|---|---|---|
| UI says *"Cannot reach the API"* | API asleep or `API_BASE_URL` wrong | Open `<api-url>/health` to wake it; check the UI's `API_BASE_URL` |
| API won't start: `SEED_CLERK_PASSWORD must be set in production` | Password variables missing or under 10 characters | Set them on the API service |
| Many invoices `failed` with `429` | Gemini free-tier rate limit | They retry 3 times automatically; Retry the rest, or move to a paid Gemini plan |
| *"Page image not available"* or Retry says *"no longer stored"* | Local storage on the free plan was wiped by a restart | Expected with local storage: re-upload the file, or [switch to R2](#switch-to-cloudflare-r2-permanent-file-storage) |
| Page images missing after switching to R2 | R2 endpoint, bucket name or keys wrong | Check the `S3_*` variables; the API logs the S3 error |
| Render build fails | Usually a Docker build error | Service → *Events* / *Logs*; the build runs the same `Dockerfile` as `docker compose build`, so reproduce locally first |
| `Session expired` | Token older than 8 hours | Log in again |
